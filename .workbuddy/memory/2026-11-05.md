# ai-orchestrator · 总控台（2026-11-05）

## 定位
一句话任务 → 自动拆解成多子任务 → 分派给不同角色智能体 → 分层并行执行 → 合并成一份交付物。
用户三次确认的形态：**独立 Web 应用 + 先方案确认后执行 + 预置角色库可自定义**。

## 技术选型（刻意极简）
零依赖：Node 22 内置 http + 原生 fetch + 单页前端（无框架无构建）。`node server.js` 即跑，不需要 npm install。
数据用 `data/state.json`（原子写：tmp + rename；坏档自动备份后从空库起步）。
包结构：`server.js` + `lib/{config,llm,roles,planner,executor,store}.js` + `public/{index.html,app.js,style.css}`。

## 模型策略（实测定的，不是拍脑袋）
- 规划：`deepseek-flash`。实测同一任务 flash 27s 拆 4 个任务、角色合理；`deepseek-v4-pro` 55s 拆 4 个任务，质量无可感知差异。第一次规划失败自动升级到 strong 重试。
- 执行：双档。`architect` / `data` 走 strong（pro），其余走 fast（flash）。
- 汇总：默认 flash。**实测 184s → 42s**，合并去重类任务快模型完全胜任。
- `reasoning_effort` 参数有效（low/high/max），但 pro 在长 prompt 下 low 档没明显加速，所以没靠这个优化。
- **max_tokens 必须给大（16000）**：推理模型先思考再说话，6000 会出现 `content` 为空 + `finish_reason=length`。重试时预算翻倍。

## 关键工程坑（都踩过）
1. **`boot()` 忘调用** —— 前端整页空白、顶栏一直"连接中"、列表不渲染。`node --check` 查不出，必须真开浏览器看 DOM。
2. **SSE 订阅晚于 execute** —— 先 POST 再连 SSE，中间几百毫秒丢 `task:start`。修法：连接建立时先推 `job:snapshot`（含各任务 status/output/summary）。
3. **SSE 连接不关闭** —— 收到 `job:done` 后不 `res.end()`，客户端 `reader.read()` 永远等不到 done，e2e 脚本卡死被 SIGTERM。修法：终态事件后 250ms 主动 cleanup；已结束的任务推完快照 120ms 就关。
4. **`cleanup` 引用未初始化的 `unsub`** —— 用 `let unsub = () => {}` 提前声明，别用 `const`。
5. **Git Bash 的 `/tmp` ≠ Windows Node 的 `/tmp`** —— curl 写 `/tmp/x.json` 后 node 读不到，用工程内相对路径。
6. **管道缓冲吞输出** —— `node script.js | tail -60` 在进程被杀时输出为空，改 `> file.log 2>&1` 再 Read。
7. `task-grid` 单卡片层只占半宽 → `.task-grid:has(> .task-card:only-child) { grid-template-columns: 1fr; }`

## Prompt 设计要点（这是产品质量的源头）
- 规划 prompt 里对依赖的判断标准写得很硬：**B 没有 A 的产出就做不下去**才算，否则并行。第一版全链路串行（T1→T2→T3→T4→T5），加"如果你输出的是一条从头串到尾的链，几乎一定拆错了"后改善为 2~3 路并行。
- **明确禁止拆出"汇总/整合成一份文档"的任务**：系统自带汇总环节，第一版模型派了个写手去合并，纯重复劳动。
- 每个子任务拿到的是：任务卡 + 上游产出 + **兄弟任务标题**（防越界重复），不是全量上下文（会跑偏）。
- 角色 persona 写"判断标准"而不是人设："先看有没有资质，再看条款" 有用，"你是资深专家" 没用。用户加角色时界面也这么提示。

## 验证结果
- 任务 A（15 秒短视频策划）：5/5，3 波并行，汇总 6850 字，296s
- 任务 B（Java 单体迁微服务）：6/6，4 波（L3 三个同时跑），各子任务 5784~28313 字，汇总 13724 字，521s
- 并行验证用服务端记录的 `startedAt/finishedAt` 算时间重叠，不依赖 SSE 事件（订阅有延迟）
- 截图验证：`screens/plan.png`（规划态）、`screens/summary.png`（交付态），Markdown 表格渲染正常

## 已知限制
单进程内存态（重启丢失执行中任务）/ 无鉴权（只监听 127.0.0.1）/ 子任务不能读文件、不能联网、不能跑命令 / 并发数全局固定 / 本地 JSON 只留最近 200 个任务。

## 下一步该做的（按价值排序）
1. **给子任务加工具能力**（读文件 / 跑命令 / 查网页）—— 现在只能产出方案，不能产出代码
2. 执行前预估成本（任务数 × 平均 token），避免一个大任务烧几十块
3. 好分工存成模板复用
4. 失败自动降级（换角色重试一次）而不是标红等人工

## 新增：开发智能体（会真改代码的那个）

### 为什么这么拆
总控台原来的子任务只会"说"。新增的「开发智能体」在指定工作区内真读写文件、真跑命令、自己验证。
两阶段必须分开：`design`（只读 → 出方案，交人确认）→ `execute`（工具循环写代码）。
跳过 design 直接写，方向错了就是一堆白改的文件。

### 新文件
- `lib/sandbox.js` — 工作区沙箱。resolveSafe（拒绝对路径/`../`/符号链接逃逸）、命令白名单（按 `&&||;|` 切段校验首词）、DENY_PATTERNS（rm -rf/format/git push/curl/sudo/盘符绝对路径/`../`）、写前备份、runCommand（stdin 关闭 + 超时 taskkill /t）
- `lib/devagent.js` — TOOLS 七件套（list_files/read_file/search/write_file/edit_file/run_command/finish），原生 function calling。**工具报错不抛异常，作为 tool 消息回喂**——这是让它能自我纠错的关键
- `lib/devrun.js` — 运行生命周期：`data/dev.json` 持久化、emitter 按 runId 常驻跨阶段复用、工作区串行锁、rollback（备份目录镜像原路径）
- `public/dev.js` — 开发视图（方案卡/轨迹/结果卡/目录选择器）

### 踩过的坑（都很隐蔽）
1. **两个视图同时显示**：`.body{display:flex}` 的优先级压过 `hidden` 属性的 UA 样式 → 必须加 `[hidden]{display:none!important}`。
2. **SSE 阶段切换丢事件**：每个阶段新建 EventEmitter，前端一条连接挂在被丢弃的实例上 → emitter 按 runId 常驻，阶段切换只换 AbortController。
3. **`if(!isRunning) 立即关闭 SSE` 是错的**：前端先连 SSE 再 POST 启动，那一瞬间还没开始跑，立即关会把后续事件全丢。改成"只有终态才关"。
4. **历史记录里轨迹空白**：只从 SSE 快照恢复 trace，没从 `run.trace` 恢复 → 补 `traceToTrail()`，并把 `tool` 记录展开成"工具行+结果行"，按 step 变化补分隔。
5. **轨迹自动滚到底**：看历史时前几步被藏起来 → 只有 RUNNING 才跟随滚动。
6. **运行中改动数一直是 0**：`run.changes` 原来只在执行结束后一次性写入 → 在 emit 里增量 push。
7. **`blocked` 字段缺失**：非拦截命令的返回对象没有 `blocked:false`，调用方拿到 undefined。sandbox.test.mjs 抓到的。
8. **正则字符类写错**：`[\s"'=-(]` 里 `-(` 被解析成区间 → SyntaxError，改成 `(^|[^a-zA-Z0-9_.])\.\.[\\/]`。

### 验证结论（实测）
- `scripts/sandbox.test.mjs`：41 条断言全过（白名单放行 9 条、拒绝 16 类危险命令、路径越界 4 条、写保护 3 条、备份/编辑 5 条、命令执行 4 条）
- 进程内直跑：83s / 6 步，产出 `src/strings.js` + `test/run.js`，`node test/run.js` 8 例通过
- HTTP 全链路：112s / 10 步，改 2 文件跑 4 命令，15 例全过
- 总控派活（4 任务）：225s 4/4 交付，`src/date.js` 落盘，14 例全过
- 回滚实测：`{restored:["package.json"], removed:["src/words.js","test/words.js"]}`，原文件恢复、新建文件删除

### 一个真实质量问题
模型写的 `slugify` 在 `maxLength` 恰好落在词边界时会多截一段（`'hello-world-again',{maxLength:11}` 返回 `hello` 而不是 `hello-world`）。它自己写的测试没覆盖这个点。
→ 已在 devagent 系统提示里加第 7 条"边界自查"：用空串、边界值、边界值±1、null 额外跑一遍，发现反直觉就改代码不要改测试。
**结论：它的自测只证明"它自己想到的用例"通过，不等于正确，关键模块仍需人 review。**

## 新增：架构智能体（只出文档，不改代码）

### 为什么是两段式，且中间必须停
架构设计的分水岭不在"写文档"，在"选哪条路"。同一句"app.js 该不该拆"，选"原生 ESM 拆分"和选"保持单文件只做分层"产出的文档是反的。所以拆成 `diagnose`（只读扫项目 → 问题清单 + 2~3 候选方案）→ 用户选方向 → `design`（工具循环写 docs）。诊断完是独立终态 `DIAGNOSED`，不是过渡态。

### 关键设计：诊断不是把代码丢给模型
`lib/archprofiler.js` 纯本地算画像（0 token，42ms/49 个 Java 文件，36ms/19 个 JS 文件）：源码根推断、模块聚合、import 解析（JS/TS/Java/Kotlin/Python/Go）、DFS 环检测、五层分层违规、上帝模块、耦合热点。画像渲染成文本喂给模型，它看到的是"你有 3 个环、2 处分层违规、1 个 67% 出度的上帝模块"，不是"请分析这个项目"。

### 新文件
- `lib/archprofiler.js` 画像扫描（导出 `profile` / `depsOf`）
- `lib/archagent.js` 两段式智能体（导出 `diagnose` / `design` / `docPathCheck` / `overwriteVerdict`）
- `lib/archrun.js` 生命周期（`CREATED→SCANNING→DIAGNOSED→DESIGNING→DONE`，另有 `INTERRUPTED`）
- `public/arch.js` 架构视图
- `scripts/archprofiler.test.mjs`（19 条）、`archguard.test.mjs`（19 条）、`archhttp.mjs`

### 踩过的坑（都是真跑出来的）
1. **测试代码被算进依赖图** → `src/test/java` 5 个文件变成 `(outside)` 模块，凭空造出假耦合。加 `TEST_PATH_RE`/`TEST_FILE_RE`，测试文件单列计数。
2. **备份目录被当成源码扫** → `data/dev-runs/<id>/backup/src/*.js` 被扫成模块还造出假环。加 `SKIP_PATH_RE`（`dev-runs|arch-runs|backup|.workbuddy|.scratch|cache`）。
3. **平铺 `lib/` 被判成源根** → 12 个文件全落 `(root)`，`lib` 误报成 67% 上帝模块。`inferSourceRoot()` 加容器性校验（该目录代码全平铺就往上退一层），上帝模块过滤容器名。
4. **`search` 的 glob 传路径永远匹配不到** → 原来统一拿 `basename` 比对，`public/app.js` 返回 0 条，模型反复试 5 次。改成 glob 含 `/` 时按 `f.path` 匹配。**这个 bug 同时影响开发智能体**。
5. **模型第 7 步就调 `finish` 想收工** → 7 步 219745 token 全在读文件，一份文档没写。工具层拦截：`docs.length===0` 时拒绝 finish 并回喂「[拒绝] 你的交付物是 docs/ 下的 Markdown，不是聊天正文」，连续拒 3 次才中止。
6. **同一个文件被读三次**（`app.js` 1065 行，每次 15k token，单步 60~120 秒）→ 重读只回显前 4KB；首读限 16KB；读超 12 个文件直接抛错；预算过半还没动笔就强制催写 README。
7. **进度催不动导致死循环** → 催促次数原来用 `trace.filter(无calls).length` 算，而空响应根本不进 trace，永远到不了上限。改独立 `idleCount` / `nudgeCount`，工具执行后归零。
8. **空响应推进历史被 400 拒绝**（`content or tool_calls must be set`）→ `if (text || calls.length)` 才 push，`devagent` 同步修。
9. **`ctx.emitter` 不存在** → `finally` 里的清理永远不执行。改 `emitterFor(runId)` + 60s 后 `removeAllListeners`。

### 收尾时又发现两个真问题（2026-11-06 修）
10. **进程被杀后状态不落终态** → `run` 卡在 `DESIGNING`，列表里永远显示"进行中"，点了没反应。`load()` 里加启动收尾：`CREATED/SCANNING/DESIGNING` 一律改 `INTERRUPTED`，补 `finishedAt`，并提示"已写出的文档仍保留"。
11. **两轮不同主题写同一 `docs/architecture/` 互相覆盖** → 第二轮从 ADR-001 重新编号，和第一轮撞车；`README.md`/`architecture.md` 被整份换掉，目录里两套结论互相矛盾。修法两条：① `design()` 开头 `listExistingDocs()` 把历史文件清单塞进 prompt，要求 ADR 编号接着最大号往后排、文件名带主题；② `write_doc` 加 `overwriteVerdict()` —— 文件已存在且不属于本轮、又没传 `overwrite:true` 就直接拒。只认布尔 `true`，不认字符串 `'true'`。

### 验证结论（实测）
- `archprofiler.test.mjs` 19 条 / `archguard.test.mjs` 19 条 / `sandbox.test.mjs` 41 条，全过
- 拿本工程开刀（19 个 JS 文件）：诊断 160s → 5 个问题 / 3 个方案；选方案 A 后写 **7 份文档 433 行**（README / architecture / 3 份 ADR / contracts / roadmap）
- 质量抽查：ADR 把三个 SSE handler 的 8 个差异点参数化成表；`## 后果` 都写了"好处/代价/后续约束"；风险第一条命中本工程真实踩坑"先连 SSE 再启动导致事件全丢"
- 越权：`/api/arch/runs/:id/doc?path=server.js` → 「这份文档不属于本次运行」

### 已知限制
- 只写文档不改代码 → 文档写完离重构完成还有一段人工工作
- 依赖解析只覆盖 JS/TS/Java/Kotlin/Python/Go；C#/PHP/Ruby 拿不到环和分层违规
- 单次诊断只读 14 个样本文件，超大工程代表性不足，建议先扫问题再针对子系统单开一轮
- 不做增量比对，代码演进后文档会过期
